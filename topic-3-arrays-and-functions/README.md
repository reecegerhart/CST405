## The pitch and customer story

A campus operations team plans outdoor events and needs to know how warm it will be a day ahead. A bare number is not enough for them: they want to see **which past hours drove the forecast**, and they want **every prediction stored** so a weekly review can check how the tool did.

> **As an** outdoor-events planner, **I want** a 24-hour temperature forecast that shows which of the last 48 hours it relied on, **so that** I can judge whether to trust it before committing to a tent, heaters or a cancellation.
>
> **As an** operations analyst, **I want** every served forecast logged with the model run that produced it, **so that** I can run a weekly review and compare the models fairly.

The product is the forecaster, plus the explainability (attention weights, an error band, a persistence reference) and the audit trail (`predictions` table joined to `runs`).

## Architecture

```
Streamlit Cloud (ui/app.py)  --HTTPS-->  FastAPI on Render (api/main.py)  --service key-->  Supabase Postgres
 thin client, no torch                    LSTM + attention (PyTorch)                          sequences (corpus)
 renders heatmaps                         scaler + model live here                            runs / run_artifacts
        \------------- anon key, read-only: runs, predictions, sequences -------------------->  predictions
```

| Tier | Where | What it holds |
|---|---|---|
| UI | Streamlit Community Cloud | 6 tabs; only READ access to Supabase (anon key) |
| API | Render.com | models, scaler, validation, all writes (service-role key) |
| Data | Supabase | corpus, runs, model artifacts, audit trail (RLS: anon can only SELECT) |

**Task.** Input: the last 48 hourly temperatures. Output: the temperature 24 h after the last input hour. Chronological 70/15/15 train/val/test split. Both models share the data, scaler (fit on train only), Adam, MSE loss, epoch budget and seed. The attention block is hand-written (`api/models.py`), not `nn.MultiheadAttention`.

## Setup, in order

1. **Supabase.** Create a project. SQL Editor → paste `db/migrations/001_init.sql` → Run.
2. **Local env.** `python -m venv .venv && source .venv/bin/activate && pip install -r requirements-dev.txt`. Copy `.env.example` to `.env` and fill in `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` (Project Settings → API).
3. **Load the corpus.** `python -m db.load` (downloads Jena Climate, keeps the latest 20,000 hours). No internet for the download? `python -m db.load --csv path/to/jena_climate_2009_2016.csv`.
4. **Train both models.** `python -m api.train_cli` (about a minute or two on a laptop). Writes two rows to `runs`.
5. **Tests.** `pytest -q` (offline; the live-Supabase test runs automatically when `.env` credentials are exported).
6. **Run locally.** `uvicorn api.main:app --port 8000` and, in another terminal, `streamlit run ui/app.py` (copy `ui/.streamlit/secrets.toml.example` to `ui/.streamlit/secrets.toml` first).
7. **Deploy API.** Render → New → Blueprint → this repo (`render.yaml`). Add env vars `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`.
8. **Deploy UI.** share.streamlit.io → new app → `ui/app.py`. Under Secrets paste `API_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY` (the anon key, never the service key). Set the app's working directory to the repo root so the Model Card tab finds `MODEL_CARD.md`.
9. **Results table.** `python -m db.readme_table` and paste above.

## API

| Method | Path | Purpose |
|---|---|---|
| POST | `/predict` | Forecast +24 h; returns the 48×48 attention matrix; logs the prediction |
| POST | `/predict_batch` | Up to 50 windows at once; each logged |
| GET | `/predictions` | Recent logged predictions |
| POST | `/train` | Read corpus from Supabase, train one model, persist the run |
| GET | `/runs` | Recent runs with metrics |
| GET | `/healthz`, `/version` | Liveness (incl. Supabase ping); git SHA, torch version, project ref |

**Validation.** A window must be exactly 48 JSON numbers (strings, booleans, nulls are rejected rather than coerced), finite, between -60 and 60 °C. Batches are limited to 50.

## Tests (`tests/`)

`test_validation.py` (length and dtype), `test_attention_shape.py` (48×48, rows sum to 1, matches the formula by hand), `test_regression.py` (frozen weights + frozen input → frozen forecast), `test_supabase_logging.py` (`/predict` writes a `predictions` row that joins to its `runs` row, offline and live), `test_health.py`.
